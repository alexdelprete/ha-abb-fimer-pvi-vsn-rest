# Release v1.5.6

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.6/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.6)

**Release Date:** 2026-07-06

**Type:** Minor release — 3-phase inverter support (String 3 + per-phase AC measurements)
and a VSN700 leakage-current correctness fix.

This is the stable release of the changes previously shipped as v1.5.6-beta.1 and
v1.5.6-beta.2. All work here was driven by issue #64 (ABB/FIMER TRIO-TM-50.0-400-EU on a
VSN700 datalogger).

## What's Changed

### Added

- **Support for a 3rd MPPT channel (String 3).** Inverters with three independent MPPT
  inputs (e.g. TRIO-TM-50.0-400-EU) now expose String 3 **Voltage**, **Current**, **Power**,
  per-string **Energy**, and **DC-input State** entities, at full parity with String 1 and 2.
  Previously only String 1 and 2 were mapped, so all String 3 data points were missing.
- **3-phase AC grid measurements.** Added, for 3-phase inverters:
  - Per-phase grid **voltage** — `VgridR/S/T` → *Voltage AC - Phase A-N / B-N / C-N*
  - **Line-to-line voltage** — `VgridRS/ST/TR` → *Voltage AC - Phase A-B / B-C / C-A*
  - Per-phase **current** — `IgridR/S/T` → *Current AC - Phase A / B / C*
  - Inverter **Internal (DC-box) temperature** — `TempInt` → *Temperature - Internal*

  Point meanings were verified against the device's live values (234 V phase-N,
  405 V line-line, ~14 A per phase) and the FIMER TRIO register map. Previously a 3-phase
  inverter exposed no per-phase AC voltage/current entities. Single-phase inverters report
  phase A-N as `Vgrid` while 3-phase inverters report it as `VgridR` (the same register);
  this is resolved with a runtime normalization alias, so both device families share the one
  *Voltage AC - Phase A-N* sensor.

### Fixed

- **VSN700 leakage current reported 1,000,000× too high.** The VSN700 leakage-current points
  (`IleakInv` / `IleakDC` — the DC-AC and DC-DC leakage sensors) are reported by the
  datalogger in µA, but were being multiplied by 1000 as if they were Amps — yielding values
  a million times too large (e.g. ~11.89 mA displayed as ~11,890,000 mA). They are now
  correctly converted µA → mA (÷1000). **This affects all VSN700 installations** — the two
  leakage sensors will change value (downward by 1,000,000×) after updating.

### Documentation

- Documented the datapoint relationship model (predominantly 1:1:1 VSN700:VSN300:SunSpec,
  with N:1 exceptions handled by the normalization layers) in `CLAUDE.md`.
