# Release v1.5.12

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.12/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.12)

**Release Date:** 2026-08-29

**Type:** Patch release — fix for duplicate meter unique IDs across multiple VSN config entries, plus standalone client fixes and new reference captures.

Includes all changes since v1.5.11. Previously published as v1.5.12-beta.1 and field-confirmed by the reporter on the exact dual-VSN700 / dual-Eastron topology from the issue (migration verified, both meters fully populated, no duplicate-ID errors, registries clean).

## What's Changed

### Fixed

- **Duplicate meter unique IDs across multiple VSN config entries** (Reported in #74, thanks to Tropie1988 [@Tropie1988](https://github.com/Tropie1988) for the detailed report, the tested local workaround, and exemplary beta testing) — Third-party meters (e.g. Eastron SDM230) report a placeholder device ID (`000000EASTRON-1PH0000`) that is identical on every VSN logger. With two config entries, the second meter's entities were rejected with "does not generate unique IDs" errors and both meters merged into a single Home Assistant device. Meter entity unique IDs and device registry identifiers are now namespaced with the logger serial number (which is unique per config entry). A one-time config entry migration (v8→v9) rewrites existing meter entities and devices in place, so entity IDs, history, and long-term statistics are fully preserved.

- **Standalone VSN REST client** (`scripts/vsn-rest-client/`, issues found during #74 testing):
  - Mapping download returned HTTP 404 — the URL pointed at the old `master` branch and a `docs/` path that no longer exists; it now fetches the runtime mapping from `main`, so `*_normalized.json` is generated again.
  - `/v1/feeds` can take well over the 10s default timeout on some VSN700 units; the feeds fetch now uses a 60s timeout floor.
  - Endpoint timeouts now degrade gracefully (warning + partial output) instead of crashing the script with a raw `TimeoutError`.
  - The datalogger is no longer listed twice in discovery output (synthetic status-based entry + livedata entry) — the client now dedupes exactly like the integration's discovery module.

### Added

- **Reference captures for the dual-VSN700 / Eastron SDM230 topology** (contributed by [@Tropie1988](https://github.com/Tropie1988)) — raw discovery/status/livedata/feeds captures from both loggers plus HA diagnostics, in `docs/vsn-data/vsn700-data/` (`tropie1988_*`). These are the first samples in the collection of a third-party meter with a placeholder device ID, and of the Eastron point set (`DynamicFeedInCtrl`, `HousePgrid_*`, `MeterPgrid_*`, `EGridImport`/`EGridExport`, `E3`/`E6`/`E7` series).

## Not Affected

- Inverters, batteries, and dataloggers have real serial numbers/MACs — their unique IDs and identifiers are unchanged, and no migration touches them.
- Single-entry installations upgrade transparently: the migration rewrites the meter in place with no visible change (same entity IDs, same history).
