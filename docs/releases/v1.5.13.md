# Release v1.5.13

**Release Date:** 2026-09-20

**Type:** Patch release — HA 2026.9 compatibility fix for entity renames.

## What's Changed

### Fixed

- **Entity rename failed with `RuntimeError` on HA 2026.9** — inverter/meter devices were linked to the datalogger with the deprecated `via_device` identifier tuple. At setup HA only logs a deprecation warning (the frame is this integration), but when you rename an entity in the UI, HA re-adds it from its core `config` component, where the same deprecation raises `RuntimeError`: the entity kept its registry entry but never got a state again until a full restart. Devices now link with `via_device_id`, the datalogger's registry id, which the integration already stores before the sensor platform loads. The stored id is cleared if the datalogger device is deleted from the UI, so a stale reference is never passed (HA 2026.9 rejects device info pointing at an unregistered id). `via_device` is scheduled for removal in HA 2027.8. No user action required, no entity IDs change.

### Changed

- **CI and pre-commit tooling pinned** (synced from ha-integration-template) — pymarkdownlnt 0.9.39, ruff 0.16.8, ty 0.0.82 and yamllint 1.38.0 now run at the same release in CI, the pre-commit hooks and the dev extras, so local checks match CI. No runtime impact.
