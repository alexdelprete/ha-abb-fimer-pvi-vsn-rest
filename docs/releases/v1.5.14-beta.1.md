# Release v1.5.14-beta.1

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.14-beta.1/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.14-beta.1)

**Release Date:** 2026-09-27

**Type:** Beta release — expected outage handling for inverter-powered dataloggers.

## What's Changed

### Added

- **Expected outage handling** (Reported in #79, thanks to piejanssens [@piejanssens](https://github.com/piejanssens)) — a new option in the integration settings stops the nightly "Cannot connect" repair issue on inverter-powered dataloggers (a VSN300 goes dark with the inverter every evening). Three modes:
  - **Off** (default): unchanged behaviour, failures are always reported.
  - **Auto-detect**: an outage that begins after the inverter had already stopped producing, with the sun below the *daytime threshold*, is treated as expected: no repair issue, no device trigger, no recovery script and no recovery notification. If the datalogger is still unreachable once the sun is above the threshold, normal failure counting starts and you are notified as before. The threshold is learned from your plant's own power-down/power-up sun elevations (last 14 overnight outages, highest value plus 2°; 10° until 3 samples exist). Requires the Home Assistant location to be set.
  - **Fixed time window**: failures inside a daily start/end window (may cross midnight) are expected.
- The learned values are visible in the integration's diagnostics download under `coordinator.expected_outage` (mode, daytime threshold, number of samples, the power-down and power-up series).

## Testing Focus

Please test with **Auto-detect** on a VSN300 (or any datalogger that powers off with the inverter):

1. Settings → Integrations → ABB/FIMER PVI VSN REST → Configure → set **Expected outage handling** to *Auto-detect* and save (the integration reloads).
1. Evening: after the inverter shuts down, the "Cannot connect" repair issue must **not** appear and no recovery script must run. The log shows one INFO line `Datalogger unreachable during an expected outage (...)`.
1. Morning: entities come back with no recovery notification. The log shows `Datalogger back online after an expected outage of ... (power-down at x°, power-up at y°, calibration recorded, daytime threshold z°)`.
1. After 2 or 3 nights, download diagnostics and check `coordinator.expected_outage`: `calibration_samples` should grow, and `daytime_elevation_threshold` should switch from the default 10° to your plant's own value once 3 samples exist. Please paste that block in the issue.
1. Real fault check (optional): during the day, cut power to the datalogger or block its network for a few minutes. The repair issue must appear after the usual number of failures, and the recovery notification must follow when it is back.
1. If you prefer a fixed schedule, try **Fixed time window** with your own start/end times and confirm the same behaviour inside/outside the window.

## Not Affected

- Users who leave the option on **Off** see no change at all.
- Dataloggers with their own power supply (VSN700, battery systems) stay reachable overnight; a night-time failure there is real, so leave the option off or use a window that fits your setup.
