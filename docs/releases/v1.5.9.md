# Release v1.5.9

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.9/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.9)

**Release Date:** 2026-07-08

**Type:** Patch release — completes the VSN700 status-entity fix from v1.5.7/v1.5.8.

## What's Changed

### Fixed

- **VSN700 status entities were still `Unavailable`** (Reported in #64) — The earlier
  attempts (v1.5.7, v1.5.8) did not fully fix it. The VSN700 state points still carried a
  numeric `Suggested Display Precision` of `0` in the generated mapping, while the
  already-working VSN300 state points carry none. That precision made Home Assistant treat
  the mapped-to-text value ("Run") as numeric — it tried `int("Run")`, raised `ValueError`,
  and the entity failed to add (`Unavailable`). The VSN700 state names (`GlobState`,
  `InvState`, `DC1/2/3State`) are now managed **exactly** like the VSN300 names — no
  device_class, no state_class, and no display precision — so the operating-state entities
  render as text (**Run**, **MPPT**, **No Alarm**, …). A regression test now asserts every
  state-mapped point stays text-only in the generated mapping.
