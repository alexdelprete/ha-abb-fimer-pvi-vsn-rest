# Release v1.5.14-beta.3

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.14-beta.3/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.14-beta.3)

**Release Date:** 2026-10-02

**Type:** Beta release — expected outage handling refinements.

## What's Changed

### Changed

- **Window times only appear for the fixed window mode.** The start and end of the expected outage window are now asked in a second options step that appears only when you choose *Fixed time window*. With *Auto-detect* or *Off* the times are no longer shown, which made it look like auto mode used them. Times you saved earlier are kept, so switching back to the fixed window restores them.

### Fixed

- **Nights interrupted by a Home Assistant restart are now learned.** Auto-detect kept the outage in progress only in memory, so a restart while the logger was dark (for example after an overnight update) skipped that night and delayed the switch from the starter rule to the learned rule. The outage start is now stored with the integration's settings and picked up again when the logger comes back in the morning. A stored outage older than 20 hours is discarded instead of learned.

## Testing Focus

1. Install v1.5.14-beta.3 (HACS, beta versions enabled) and restart Home Assistant. Keep **Expected outage handling** on *Auto-detect*.
1. Open the integration options: the window times should no longer be shown. Pick *Fixed time window* and submit to see the second step with the times, then switch back to *Auto-detect*.
1. Restart Home Assistant one evening after the logger has gone dark. The next morning the diagnostics (`coordinator.expected_outage`) should still show that night counted in `nights_learned`.
