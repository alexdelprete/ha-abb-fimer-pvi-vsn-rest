# Release v1.5.7

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.7/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.7)

**Release Date:** 2026-07-07

**Type:** Patch release — VSN700 status entities now render as human-readable text.

## What's Changed

### Fixed

- **Status entities showed raw numbers instead of text on VSN700** (Reported in #64) — The
  operating-state entities (**Global State**, **Inverter State**, **DC Input 1/2/3 State**)
  displayed as raw codes (`6.0`, `2.0`, …) on VSN700 dataloggers instead of readable text
  ("Run", "MPPT", …). There were two causes, both fixed:
  1. The state-code → text maps were keyed only on the VSN300/SunSpec names
     (`GlobalSt`/`InverterSt`/`DcSt1-3`), while VSN700 uses different names
     (`GlobState`/`InvState`/`DC1-3State`). The VSN700 names are now aliased to the same maps.
  1. VSN700 encodes the codes as JSON floats (`6.0`) while the decoder only accepted ints;
     it now accepts float-encoded codes. VSN300 behaviour is unchanged.

  Bit-field entities (**Warning Flags** and the **Derating Flags**) remain numeric — their
  bit definitions are not published by ABB (verified against the TRIO-50 SunSpec PICS, the
  ABB Aurora protocol library, and the web).
