# Release v1.5.12-beta.1

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.12-beta.1/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.12-beta.1)

**Release Date:** 2026-08-28

**Type:** Beta release — fix for duplicate meter unique IDs across multiple VSN config entries.

## What's Changed

### Fixed

- **Duplicate meter unique IDs across multiple VSN config entries** (Reported in #74,
  thanks to Tropie1988 [@Tropie1988](https://github.com/Tropie1988) for the detailed
  report and tested local workaround) — Third-party meters (e.g. Eastron SDM230) report
  a placeholder device ID (`000000-Eastron_1PH-0000`) that is identical on every VSN
  logger. With two config entries, the second meter's entities were rejected with
  "does not generate unique IDs" errors and both meters merged into a single Home
  Assistant device. Meter entity unique IDs and device registry identifiers are now
  namespaced with the logger serial number (which is unique per config entry). A
  one-time config entry migration (v8→v9) rewrites existing meter entities and devices
  in place, so entity IDs, history, and long-term statistics are fully preserved.

## Testing Focus

For users with **one** VSN config entry and a meter:

- After upgrading, your meter device and all its entities should look exactly as
  before: same entity IDs, same history, same statistics. The only visible change is
  internal (unique IDs and the device identifier now carry the logger serial).

For users with **two or more** VSN config entries whose meters share the same generic
device ID (the issue #74 scenario):

- Each config entry should now show its own meter device with a full set of entities,
  and the log should contain no "does not generate unique IDs" errors.

## Not Affected

- Inverters, batteries, and dataloggers have real serial numbers/MACs — their unique
  IDs and identifiers are unchanged, and no migration touches them.
