# Release v1.5.14

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.14/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.14)

**Release Date:** 2026-11-21

**Type:** Minor release: expected outage handling for inverter-powered dataloggers, Home Assistant 2026.11 baseline, energy sensor unit fix.

All changes since v1.5.13, including those published in v1.5.14-beta.1, beta.2 and beta.3.

## ⚠️ Before You Upgrade

- **Home Assistant 2026.11.0 or newer is required.** The integration now uses APIs introduced in Home Assistant 2026.11. HACS does not offer this update to older Home Assistant versions.

## What's Changed

### Added

- **Expected outage handling** (Reported in #79, thanks to piejanssens [@piejanssens](https://github.com/piejanssens)). A new option in the integration settings stops the nightly "Cannot connect" repair issue on inverter-powered dataloggers (a VSN300 goes dark with the inverter every evening). Three modes:
  - **Off** (default): unchanged behaviour, failures are always reported.
  - **Auto-detect**: a dropout is judged at the last good poll. If the sun was low **and** the plant was producing little, the outage is expected: no repair issue, no device trigger, no recovery script and no recovery notification. If the logger is still dark once the sun is above the plant's start-up elevation, normal failure counting starts and you are notified as before. Requires the Home Assistant location to be set.
  - **Fixed time window**: failures inside a daily start/end window (may cross midnight) are expected. The start and end times are asked in a second options step that appears only for this mode.
- **Auto-detect learns your plant's night pattern.** Every overnight outage is recorded as a night: sun elevation and power when the logger switched off, sun elevation when it came back. For the first 5 nights a built-in starter rule applies (sun below 0° and power below 60 W, start-up by 10°). From then on the bounds are learned: highest switch-off elevation + 2°, highest switch-off power × 1.5 + 10 W, highest start-up elevation + 2°. The last 14 nights are kept, so the bounds follow the seasons, and a night far off the usual pattern is ignored. A night interrupted by a Home Assistant restart is still learned. Back-tested on 16 real nights of a VSN300 + PVI-10.0-OUTD: no evening alert and no false morning alert.
- **Diagnostics** show the active rule (starter or learned), the learned nights, the bounds and today's resulting window in clock time, under `coordinator.expected_outage`.

### Changed

- **Repair issues are linked to the integration entry.** The connection, partial-discovery, datalogger-silent and unsupported-firmware issues now appear on the integration's page and are removed together with the entry.
- **Sensors are renamed in place.** Changing a sensor's entity ID, including the entity ID regeneration in the integration options, now updates the entity in place instead of removing and re-adding it.
- **Marketplace category.** The manifest declares the `energy.solar_batteries` category.
- **Coordinator passes its config entry explicitly.** The data coordinator relied on the context variable Home Assistant sets during setup, which Home Assistant deprecates. No behaviour change.
- **Validation engine.** Configuration and options forms use probatio, Home Assistant's validation engine, instead of voluptuous. No user-visible change.
- **Development tooling.** Tests run on `pytest-homeassistant` 2026.11.0, the test package published by Home Assistant core, replacing `pytest-homeassistant-custom-component`; `homeassistant-stubs` is no longer used.

### Fixed

- **Energy sensors 1000x too small after a setup on a zero reading** (Reported in #90, thanks to truonganvna [@truonganvna](https://github.com/truonganvna)). The energy unit was reported as `Wh` when a reading was 0 or empty, and as `kWh` otherwise. A sensor fixes its unit when it is created, so an energy counter created while at 0 (typically the VSN700 "Energy AC - Produced (Since Restart)" right after the logger restarts at dawn) kept `Wh` while its values were in kWh, and Home Assistant divided them by 1000 again. Energy sensors now always report `kWh`. Affected sensors return to the correct scale after the update; statistics already recorded with the wrong scale are not corrected automatically (Developer Tools > Statistics can adjust them).
- **"Cannot connect" repair stuck after a restart during an outage.** The repair is persistent, but the integration only remembered in memory that it had raised it, so after a Home Assistant restart or reload while the logger was dark nothing ever removed it. It is now cleared as soon as setup reaches the datalogger again.
- **hassfest validation.** `aiohttp` is removed from the manifest requirements: it ships with Home Assistant, and hassfest rejects it in custom integrations. No functional change.
- **Type check on reload scheduling.** The unknown-devices reload now uses the config entry's own id, and the full-recovery reload is skipped when no entry id is set. No behaviour change in normal operation.

### Removed

- **Local translation of the "Reconfiguration successful" message.** Home Assistant translates it centrally since 2026.10.

## Notes for Beta Testers

- Compared with v1.5.14-beta.3, this release adds the Home Assistant 2026.11 changes (minimum version, repair issues linked to the entry, in-place renames, Marketplace category, probatio) and the energy unit fix from #90.
- Learned nights and the expected outage settings are kept.
