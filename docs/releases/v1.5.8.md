# Release v1.5.8

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-fimer-pvi-vsn-rest/v1.5.8/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-fimer-pvi-vsn-rest/releases/tag/v1.5.8)

**Release Date:** 2026-07-07

**Type:** Patch release — fixes a VSN700 status-entity regression introduced in v1.5.7.

## What's Changed

### Fixed

- **VSN700 status entities showed `Unavailable` after v1.5.7** (Reported in #64) — The
  v1.5.7 status-text fix regressed the VSN700 operating-state entities (**Global State**,
  **Inverter State**, **DC Input 1/2/3 State**) to `Unavailable`. VSN700 sends the state
  codes as floats (`6.0`), and v1.5.7 translated them to text in `native_value` while the
  entity was still driven by a float value, which Home Assistant rejected. The fix mirrors
  the already-working VSN300 path: the normalizer now casts the VSN700 state/flag codes to
  **int** (so they arrive exactly like VSN300's ints) and the state → text mapping keeps its
  original int-only logic. Both datalogger models now take the identical, proven path, and
  the status entities render correctly (`Run`, `MPPT`, `No Alarm`, …). Flag bit-fields
  (**Warning Flags**, **Derating Flags**) also display as clean integers instead of `64.0`.
